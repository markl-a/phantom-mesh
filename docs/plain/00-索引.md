# 00-目錄（從這裡開始讀）

這份是整套白話文件的目錄，會告訴你這六份文件分別在講什麼，以及建議先看哪一份。不需要懂程式，也不需要懂產品開發，只要想了解這個工具想解決什麼問題，就可以從這份目錄開始看。

先講一件事：我想做的這個工具，我給它取了個名字，叫 **Phantom**。後面的文件裡只要看到「Phantom」，指的就是它。另外，文件裡的「我」，是指寫這套文件、想做出這個工具的人（也就是作者），不是指正在看的你。

這整套文件會用最白話的方式，說清楚我想做的這個工具到底是什麼、我平常會怎麼用它、它需要幫我做哪些事，以及怎麼判斷它真的做好了。這裡不會出現寫程式的內容，會盡量用一般人也能理解的說法來寫。如果你是第一次看，建議照下面的順序一份一份往下讀就好；每份都不長，看完你就會比較清楚 Phantom 想解決什麼問題。

## 文件清單與建議閱讀順序

1. [01-我到底要什麼](01-我到底要什麼.md) — 用一句話講清楚我想做的這個工具是什麼、為什麼想要它。**最先讀這份。**

2. [02-我會怎麼用它](02-我會怎麼用它.md) — 講我平常一天會怎麼用到它，從早到晚有哪些時刻會找它幫忙。

3. [03-真實情境](03-真實情境.md) — 用幾個很具體的小故事，說明它在真實情況裡會怎麼幫上忙，讓前兩份提到的東西更好想像。

4. [04-它要會做哪些事](04-它要會做哪些事.md) — 把它需要做到的事一條一條列出來，像一張「能力清單」。

5. [05-怎麼確認每個功能真的做好了](05-怎麼驗收每個功能.md) — 每一項能力做好了，要怎麼確認它「真的能用、不是只有嘴上說好」。

6. [06-讓 Phantom 幫忙把自己變得更好](06-讓phantom幫忙造自己.md) — 講一個比較深入的想法：做出 Phantom 之後，反過來請它幫忙改進它自己，讓它愈用愈好用。**最後讀就好，不看也不影響你理解主軸。**

### 給趕時間的人

只看 1、2、3 三份就夠了，這三份能讓你大致掌握這件事在做什麼（差不多七成）。第 4、5 份想看得更仔細時再翻；第 6 份是比較深入的延伸想法，不看也沒關係。
