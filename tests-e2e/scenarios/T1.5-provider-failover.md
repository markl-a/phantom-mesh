# T1.5 — Provider failover(故意設錯第一個 key,看自動切換)

**Source**: doc 28 §2 Tier 1 + doc 29 §4 **V1**(12 provider)
**Status**: 🟢 可跑

## Prereqs
- [ ] spectyn binary verified
- [ ] 至少 2 個 provider key 設好(e.g. Anthropic + Groq)
- [ ] `agents.toml` 內 `[agent.master] providers = ["anthropic", "groq", ...]` 順序明確

## Steps
1. 看當前設定:
   ```bash
   spectyn providers              # 看到 anthropic 在第 1、groq 第 2
   ```
2. **故意把第一個 provider 弄壞**:
   ```bash
   # 方法 A:env 設成空
   ANTHROPIC_API_KEY=invalid_key spectyn exec "say hello" --json
   ```
   或
   ```bash
   # 方法 B:暫時 unset
   unset ANTHROPIC_API_KEY
   spectyn exec "say hello" --json
   ```
3. 觀察 `--json` stream:
   - 應該有一個 `Error` event 或 retry log 顯示 anthropic 失敗
   - 然後 `Route { provider: "groq", ... reason: "anthropic failed: 401" }`
   - 最後 `Done` 用 groq 完成

## Pass criteria
- [ ] spectyn **不崩潰**
- [ ] trace / log 顯示 fallback 動作
- [ ] 最終回應來自第 2 個 provider
- [ ] 整個流程 < 30 秒(不該卡 anthropic timeout)

## Failure modes
- 沒 fallback → check `agents.toml [agent.master] providers = [...]` 設定
- 一直 timeout → check `agents.toml` 內 provider timeout 設定
